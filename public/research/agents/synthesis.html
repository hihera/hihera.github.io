一页结论

  1. 编程与办公合流：Codex 并入 ChatGPT 与 Work 共用引擎，Claude Cowork 复用 Claude Code 架构，TRAE 中国版把编程与办公合成一个产品，Cursor 与 Grok 合进同一订阅，WorkBuddy 与 CodeBuddy 共享积分——同一套执行引擎服务两类人群S2
  2. 开发者市场格局清晰：JetBrains 调研显示 Claude Code 工作使用率 39%、GitHub Copilot 21%、Codex 16%、Cursor 12%、Antigravity 6%；Codex 半年增长约 5 倍，Cursor 从 18% 下滑S1
  3. 办公 Agent 的差异在入口与上下文：能力趋同（成品文件、电脑操作、定时任务），胜负取决于能否接入用户已有的工作上下文——Google 的 Workspace、字节的飞书、腾讯的企业微信、微软与 Anthropic 的合作S2
  4. 新形态：常驻云电脑的个人 Agent：ChatGPT 的 dot、Grok Bot、Gemini Spark、Muse、Manus Cloud Computer、Cursor 云端 Agent 都给 Agent 一台持久的云电脑，关机也能干活S2
  5. 竞争转向额度、捆绑与信任：额度政策反复（Codex）、订阅捆绑（X Subscription）、断供风险（OpenAI 停止向 Cursor 供应模型）、地缘监管（Manus、TRAE）成为影响格局的关键变量S2

02定位格局

用统一的 12 项能力评级，把“编程能力”和“办公与通用能力”分别汇总，可以看到三类产品的位置。

读图要点：编程型产品（Claude Code、Codex、Cursor）都在补办公能力，其中 Codex 借助同一应用里的 ChatGPT Work 已接近“全能型”；办公型产品普遍不碰编程，交给同厂商的编程产品；Gemini 是唯一在两条线上都给出完整产品的厂商，但能力分散在多个入口（分析意见）。

03能力对比

几乎人人都有的能力（标配）

  • 定时与自动化：10 款为核心能力
  • 扩展生态：Skills、MCP、插件成为通用语言

仍有明显差异的能力

  • 代码审查：只有 Claude Code、Codex、Cursor 做成独立产品
  • 多模型可选：只有 TRAE 做到核心；模型厂商的产品几乎都只用自家模型
  • 企业管控：面向个人的 Muse、Manus 较弱

三个趋势（分析意见）：一是订阅合并，同一厂商的编程与办公产品共用一个订阅和用量池；二是积分化，用一个统一单位覆盖不同成本的任务（文字、代码、视频）；三是捆绑扩张，把 AI 额度和云存储、社交会员、办公套件打包，降低用户感知价格。

结论：2026 年独立的 Agent 应用越来越少——Cursor 被 SpaceX 收购、Manus 的收购被叫停后独立、TRAE 并入豆包。模型厂商用“自家模型 + 自家应用”的垂直整合挤压中立应用的空间，而上游断供（OpenAI 对 Cursor、Anthropic 对 TRAE 国际版）让这种挤压变得更直接（分析意见）S2。

07趋势判断分析意见

  • 一个引擎，多种产品：Agent 的执行层（文件读写、工具调用、沙箱、权限、云端运行）正在标准化，产品差异转向交互、场景与分发。
  • 从“我问你答”到“常驻队友”：dot、Grok Bot、Spark、Muse 都是持续运行、主动汇报的 Agent，下一阶段的竞争是谁更懂用户、更值得信任。
  • 上下文就是护城河：能接入邮件、文档、群聊、组织权限的厂商（Google、字节、腾讯、微软生态）在办公场景天然占优。
  • 开放标准成为默认：MCP、Skills、AGENTS.md 被各家普遍支持，用户的配置可以在产品之间迁移，锁定效应减弱。
  • 安全设计前置：Muse 的 Sentinel、Claude 的隔离云沙箱、企业版的消费上限与审计，说明“Agent 会出错、会被攻击”已成为行业默认假设。
  • 地缘与资本重塑格局：收购、断供、监管叫停在一年内多次改变产品的归属与能力边界。

08对 AI 产品团队的启示分析意见

如果你做 Agent 应用

  • 避开模型厂商正面覆盖的通用场景，找它们不愿做或做不好的垂直场景
  • 准备多模型与开源模型兜底，降低断供风险
  • 把企业上下文（权限、知识、流程）做深，这是模型厂商难以复制的部分

如果你在大厂做 AI 产品

  • 把执行引擎做成平台能力，编程、办公、个人助手共用
  • 利用已有入口（IM、文档、OS）分发 Agent
  • 控制产品线数量，避免同类产品内耗

定价与商业化

  • 额度是体验的一部分，调整要提前沟通并给过渡期
  • 积分制适合多模态任务，但要让用户能预估成本
  • 企业市场靠席位 + 共享用量 + 管控功能打开

信任与安全

  • 默认 Agent 可能出错或被提示注入，用架构限制损失
  • 关键操作需用户确认，提供完整审计记录
  • 模型来源、数据去向要主动披露
